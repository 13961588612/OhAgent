# 学习路线图与阶段依赖

> 23 个阶段，6 个部分。阶段数目不固定，按**能力依赖**而非章节均分设计。

## 依赖关系（→ 表示"必须先完成"）

```
s00 环境与源码地图
 └→ s01 配置系统
     └→ s02 Provider/认证 ──┐
         └→ s03 Prompt/上下文 │
             └→ s04 Agent Loop ←┘（读完 s04 才可能理解其余运行时）
                 ├→ s05 Tools
                 │   ├→ s06 权限与安全 ─┐
                 │   ├→ s07 Hooks       │
                 │   ├→ s08 Skills      ├→ s12 压缩与成本
                 │   ├→ s09 Plugins     │
                 │   └→ s10 MCP ────────┘
                 ├→ s11 Memory/Session ─→ s12
                 ├→ s13 Coordinator/Subagent ─→ s14 Swarm ─→ s15 Tasks/Cron/Autopilot

                         └────────────────────────→ s22 毕业项目
```

## 每部分的能力跃迁

| 部分 | 阶段 | 你从"会用什么"跃迁到"能造什么" |
|------|------|-------------------------------|
| I 地基 | s00–s02 | 从"照文档用 CLI"到"能解释配置与接入的全部来源" |
| II 运行时核心 | s03–s10 | 从"会写提示词"到"能开发工具/技能/插件/MCP 并治理权限与合规" |
| III 记忆治理 | s11–s12 | 从"对话会爆上下文"到"能设计长周期记忆与成本模型" |
| IV 多智能体 | s13–s15 | 从"单 Agent"到"能编排团队、隔离代码、无人值守" |
| V 交付面 | s16–s18 | 从"本地命令行"到"能接入 IM、定制终端、隔离执行" |
| VI 工程化 | s19–s21 | 从"能跑"到"可观测、可测试、可发布、可维护" |
| 毕业 | s22 | 从"会用 OpenHarness"到"能交付企业级 Agent 平台" |

## 与"资深水平"的差距检查

完成全部阶段后，用以下问题自检（全部答"是"才达标）：

- 能否画出从用户输入到模型输出、再回到 UI 的完整调用链并指出每层的治理插点？
- 能否在不改上游源码的前提下，通过配置/插件/MCP 满足 90% 的企业需求？剩下 10% 需要改哪里？
- 能否为一次线上事故（如工具越权、上下文爆炸、成本飙升、通道丢消息）定位到具体模块并给出修复方案？
- 能否制定团队的 Skill/Plugin/Hook/权限规范，并让它可测试、可审计、可升级？
